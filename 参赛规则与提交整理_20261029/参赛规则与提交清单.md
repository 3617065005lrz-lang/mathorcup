# MathorCup 2026大数据初赛：规则与提交清单

核对日期：2026年10月29日（北京时间）。适用本队选择的B题“泥石流灾害预报及防灾策略”。依据用户提供赛题包中的四份公共文件、B题PDF，以及本届官网和主办方赛氪公告整理。本文是准备清单，不是提交成功证明。

## 1. 先记住这六件事

1. **截止：2026年10月30日20:00。** 官网要求至少提前30分钟至1小时登录上传；建议本队19:00前完成首轮正式提交并核对状态。这是操作安排建议，20:00才是官方截止时间。[官网赛题公告](https://www.mathorcup.org/detail/2497)
2. **由队长用电脑登录赛氪提交。** 上传结束后还要点击“提交电子档”或“更新电子档”，看到“电子档已提交”才算成功。[提交规范公告](https://m.saikr.com/contest/notice_detail/49567)
3. **准备论文PDF、全员签名承诺书、支撑材料包。** 本队编写了程序，又使用了AI，不能把支撑材料当成完全可选；其中须有源代码和AI使用详情PDF。依据：官网报名通知第2页第9条、附带章程第5页；AI规定第2页第五部分。
4. **AI要求分布在四处：正文标注、工具参考文献、参考文献后的声明、支撑包内详情PDF。** 有AI辅助代码时还要在代码注释中说明。[本届AI规定](https://m.saikr.com/contest/notice_detail/49194)
5. **论文中文，正文30页以内，附录不限；无页眉；正文第一页从1编号，页码在页脚中央。** 第一页放题目、摘要、关键词，第二页为目录。匿名论文不能出现姓名、学校等身份信息。官方模板要求的队伍编号和赛道信息保留。依据：本地《论文格式及提交规范》第1页、官方Word模板。
6. **提交次数与队号命名有待确认，详见第7节。** 不自行把“可多次更新”理解为同一天不限次数，也不根据示例擅自增删MCB前缀。

## 2. 最终需要交什么

|材料|本队是否需要|格式与文件名|提交位置/依据|
|---|---|---|---|
|正式论文|需要|PDF；按“题号+参赛队号”命名。规范原例为`B2600001.pdf`，并非本队真实文件名|论文上传栏；格式规范第1页提交条款2|
|签名承诺书|需要|官方表格，所有实际参赛队员手写或电子签名后转PDF或图片；名称为“题号+参赛队号+承诺书”|承诺书上传栏；格式规范第2页条款3|
|支撑材料包|本队需要|ZIP/RAR；名称为“题号+参赛队号+附件”。示例`B2600001附件.zip`|支撑材料上传栏；有程序须交源码，使用AI须含详情PDF|
|AI工具使用详情说明|本队需要|**`AI工具使用详情说明.pdf`**，使用官方指定基础名称|放入支撑材料包；未见要求另设独立上传栏，不能因没有AI专用栏而省略|
|独立计算结果文档|按题目/系统要求|已查阅B题4页PDF，没有规定另交指定CSV/Excel格式、字段模板或专用结果文件名|若登录页或后续官方公告新增要求，再按其要求；目前把核心结果放论文、详细结果放支撑包|

官方材料中的“支撑材料一般可选”有条件：报名通知明确，有自己编写的程序，除论文附录外仍要提交源程序；AI规定进一步明确使用AI必须在支撑材料中交详情说明。不能只提交论文和承诺书。

### 支撑包建议目录

以下是组织建议，不是官方强制目录名。文件名前的真实队号待确认后填写。

```text
B[真实队号]附件.zip
├─ AI工具使用详情说明.pdf
├─ README_运行说明.md
├─ code/                 # 与四问最终正文相匹配的源程序
├─ config/               # 实际采用的参数、配置与随机种子（适用时）
├─ results/              # 排序、阈值、预报区间、仿真指标等结果表
├─ figures/              # 正文图及必要的仿真可视化
└─ data/                 # 必要的外源/处理后数据或下载、预处理说明
```

- 赛题原始数据按提交规范不必重复打包。
- 运行说明建议写清环境、依赖、执行顺序、输入输出与四问对应关系。章程评测标准要求代码配套详细操作说明。
- 不把GitHub链接或Overleaf链接当作已上传的实际作品文件。
- PDF图、仿真截图、结果表和程序版本要与最终论文一致。B题第四问要求明确关键参数、仿真过程和可视化结果；不能只交代码而在论文中不展示结果。
- 未查到统一公布的上传大小上限；请队长提前进入实际提交页查看。不套用其他比赛的20MB等限制，也不默认平台能接收全部大型气象原始文件。

## 3. AI材料怎么准备

依据本届《人工智能工具使用规定》第1—2页及[10月16日主办方公告](https://m.saikr.com/contest/notice_detail/49194)。适用范围包括大语言模型、生成式AI、代码辅助工具等。

### 论文与代码中的四项处理

- **正文相应位置标注：**使用AI生成的文字、分析结果、图表或参数优化内容，应说明AI贡献；不要仅在文末笼统声明而漏掉正文标注。
- **参考文献列工具：**按“[编号] 工具名称，版本/型号，开发机构/公司，使用日期”列出。具体模型、版本和日期根据各队员实际记录填写，不猜测、不统一写成未知的版本。
- **参考文献之后放使用声明：**MathorCup本届规定的位置是“后”，不要照搬其他比赛“参考文献前”的要求。
- **AI辅助编程注释：**在相应程序中注明工具名称、版本、开发机构、使用日期和实际辅助环节。

### 支撑包中的详情PDF

文件名为`AI工具使用详情说明.pdf`，应含：

1. 每个AI工具的名称与版本；
2. 具体目的与环节，如资料检索、数据处理、编程、可视化、分析、论文文字等；
3. 关键交互记录，包括重要提示词与回复；
4. 实际采纳内容、人工修改与核验情况。

这里要求“关键交互”，不是要求把所有聊天原样堆进去。整理代表性记录时，保留真实提示词、回复、采纳位置和修改过程；不用编造已经发生的人工审核。可以使用同目录的`AI工具使用详情说明_填写模板.md`，补全后导出指定名称的PDF。

### 本队现在需要据实补齐

本对话已涉及AI检索参考资料、第三问正文/摘要/模型评价文字的草拟与润色、LaTeX排版及编译检查。最终披露应覆盖实际采纳的环节，不能只写“修改错别字”，也不能声明“未使用任何AI”。其他队友使用的工具、代码和图表环节由各自补充。

官方同时要求核心建模、算法设计、求解与分析由参赛队员独立完成，并由参赛队对AI内容负责。独立完成和人工核验的具体事实应由队员按照实际工作记录确认；这份清单不代替该承诺。

## 4. 论文格式逐项核对

依据《论文格式及提交规范》第1页，以及[10月22日主办方公告](https://m.saikr.com/contest/notice_detail/49567)。

- [ ] 系统选择B题，与论文内容、承诺书一致。
- [ ] 首页包含正式论文题目、摘要、关键词，按官方模板填写队伍编号与赛道。
- [ ] 第二页是目录；正文在目录后开始。规范未明确目录超过一页时的处理，本队可优先将目录压至一页。
- [ ] 正文从阿拉伯数字1开始连续编号，页码置于每页页脚中央。
- [ ] 删除所有页眉；不把本地独立预览的页眉设置直接带入提交稿。
- [ ] 论文匿名：正文、附录、图表、截图、路径和代码输出中都检查姓名、学校等身份信息。签名承诺书单独上传，不作为论文身份页合并。
- [ ] 使用中文、可读字体；正文控制在30页以内。附录不限页，未规定固定字体、字号、行距或颜色。
- [ ] 正文引用与参考文献对应，用方括号编号，按正文首次引用次序排列。书籍引用注明页码，网络资料写访问年月日。
- [ ] 附录列实际软件名称、命令和编写的全部源程序（若有）。源文件另放支撑包并保存到正式获奖名单公布。
- [ ] AI正文标注、工具参考文献和参考文献后的使用声明齐全。
- [ ] 去掉模板占位文字：假设1/2、关键词占位、题目占位、MCB260XXXX、A/B待选、空章节等。
- [ ] 将所有独立章节合成一份正式论文PDF，检查目录页码、公式图表编号和引用。之前各节预览PDF供审阅，不是完整参赛稿。

## 5. 承诺书怎么填

依据总包内官方承诺书DOCX。

- 赛道填B。
- 参赛队号按报名系统准确填写；承诺书表头明确要求MCB打头的字母数字编号。
- 队长学校写完整校名，不含院系名。
- 实际参赛队员逐一手写或电子签名，并填写日期；不能只打姓名代替所要求的签名。
- 核对所有信息再生成PDF/图片，按规范命名，单独提交。
- 承诺书包含赛时不与团队（队员和指导教师）外人员讨论赛题、规范引用等承诺，队员签名前应阅读原文。

## 6. 队长的提交流程

1. 在电脑上使用队长赛氪账号进入[本届竞赛主页](https://www.saikr.com/vse/bigdata2026)。
2. 进入“报名管理”，找到电子档处的“点击提交”，先查看当前字段、文件大小与可修改次数提示。
3. 选择B题；按对应栏上传论文PDF、签名承诺书、支撑ZIP/RAR及系统明确要求的其他结果文件。
4. 核对文件名、赛道、队号和预览内容，点击右下角“提交电子档”；修改已有记录时点击“更新电子档”。
5. 等待处理完成，确认状态为“电子档已提交”。仅见上传进度100%或文件名不等于已正式提交。
6. 建议保存成功状态和文件列表截图，若系统支持则下载核对；本地保留最终提交文件、源程序和版本记录。这些是留存建议。
7. 官方建议至少提前30分钟至1小时操作；本队建议19:00前完成，给上传失败或格式核对留时间。

## 7. 需要队长在实际提交页/向组委会确认的事项

### A. 同一天能否重复更新

- 2026年8月修订章程第4条（官网报名通知附件第5页）写“每个队伍每天最多提交1次”。
- 10月22日发布的提交规范第2页写竞赛期间可多次删除并重新上传；修改时使用“更新电子档”。
- 两处对同一天更新是否受限没有解释清楚。本次整理不擅自判定哪条被取消；不要默认一天能不限次数更新。先在提交页核对，必要时请组委会确认后操作。

### B. 文件名是否包含MCB前缀

- 官方模板和承诺书的队号格式包含MCB，提交规范的示例是`B2600001.pdf`，没有解释二者换算关系。
- 当前材料中没有本队真实队号。不要把示例当成真实队号，也不要擅自删除或重复MCB。请根据报名系统文件命名提示或组委会答复统一三份材料名称。

### C. 文件大小、结果栏及新公告

- 所查公开规范未列统一文件大小上限；登录后的限制尚未核实。
- B题PDF未指定另交固定CSV/Excel，但提交页或后续群公告可能增加实际操作要求。
- 仅核对了公开官网/主办方公告和提供的赛题包，未读取你们参赛群内部通知。
